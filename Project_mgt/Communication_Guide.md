# 双心宝项目协同沟通指南

## 📌 沟通原则

> **少而精、异步优先、结果导向**

本项目是公益项目，所有成员均利用业余时间贡献。我们尊重每个人的时间，追求**高效、清晰、异步**的沟通方式，避免频繁打扰和无效会议。

---

## 一、核心沟通原则

### 1. 异步优先，同步必要
- ✅ **优先使用**：文档、飞书多维表格、GitHub Issue
- ⚠️ **谨慎使用**：微信群@所有人、临时会议
- ❌ **避免使用**：频繁语音电话、紧急私聊（非紧急事项）

### 2. 少而精的沟通频次
- **避免**：每日站会、频繁进度汇报
- **推荐**：每周一次异步同步 + 双周一次短会
- **原则**：非紧急问题沉淀24小时，批量处理

### 3. 结果导向的交付
- 沟通以**可交付成果**为目标
- 问题描述要附带**解决方案建议**
- 进度更新聚焦**关键节点**而非过程细节

### 4. 尊重业余时间
- 工作日晚上 22:00 后、周末非紧急事项**不@成员**
- 紧急定义：影响项目上线的blocking问题
- 响应时间：工作日 24 小时内，周末 48 小时内

---

## 二、沟通渠道与用途

### 📱 微信群（日常快速沟通）
**用途**：
- 简单问题快速确认（5分钟内能解决的）
- 临时通知与提醒
- 非正式讨论与头脑风暴

**使用规范**：
- ✅ 问题简洁明了，附带上下文
- ✅ 超过3条消息的讨论转飞书文档
- ✅ 重要结论同步到飞书文档归档
- ❌ 避免刷屏（超过5条连续消息）
- ❌ 避免@所有人（除非紧急或项目级通知）
- ❌ 避免在群里发送大文件（用飞书云文档）

**响应时效**：
- 工作日：24小时内
- 周末：48小时内
- 紧急事项标注【紧急】

---

### 📊 飞书（项目管理与文档协作）
**用途**：
- 项目文档编写与协作
- 任务管理与进度跟踪
- 会议纪要与决策记录
- 知识沉淀与资料归档

**关键工具**：

#### 1. 飞书文档
- **项目文档库**：技术方案、产品设计、知识库内容
- **会议纪要**：每次会议后24小时内完成
- **决策日志**：重要决策记录原因与结果

#### 2. 飞书多维表格
- **任务看板**：所有任务统一管理（见下文"任务管理"）
- **知识库清单**：知识条目状态追踪
- **问题跟踪表**：Bug与优化建议管理

#### 3. 飞书日历
- **里程碑事件**：关键时间节点提醒
- **定期会议**：固定会议时间预定

**使用规范**：
- ✅ 文档编写使用模板（见附录）
- ✅ 重要文档评论@相关人，24小时内回复
- ✅ 文档修改留痕，避免覆盖他人内容
- ❌ 避免创建过多碎片化文档，优先在已有文档中补充

---

### 💻 GitHub（代码与技术协作）
**用途**：
- 代码管理与版本控制
- 技术问题讨论（Issue）
- 功能需求与Bug跟踪
- 代码审查（Pull Request）

**使用规范**：

#### Issue管理
- **技术问题**：描述清楚问题、复现步骤、期望结果
- **功能需求**：说明背景、用户价值、验收标准
- **Bug报告**：附带截图/日志、环境信息
- **标签使用**：bug / feature / question / documentation

#### PR流程
- 提交前自测通过
- PR描述清晰（做了什么、为什么、如何验证）
- 小步提交，避免大PR（超过500行需拆分）
- Code Review：RAG工程师必须审核，24-48小时内完成

---

### 📝 Notion/语雀（知识库管理）
**用途**：
- 双心医学知识库内容管理
- 学习资料与教程沉淀
- 最佳实践归档

**使用规范**：
- 知识库工程师负责结构维护
- 内容更新后通知医学专家审核
- 定期（每两周）整理与归档

## 三、会议管理

### 原则：能异步解决的不开会

### 定期会议

#### 1. 双周项目同步会（必选）
- **时间**：每两周一次，周六/周日下午，30-45分钟
- **形式**：线上视频会议（腾讯会议/飞书会议）
- **参与者**：全体核心成员
- **议程**：
  1. 上两周进展回顾（5分钟/人，提前在文档准备）
  2. 遇到的问题与讨论（15分钟）
  3. 下两周计划对齐（10分钟）
  4. 其他事项（5分钟）
- **产出**：会议纪要（24小时内发飞书）

#### 2. 月度复盘会（可选）
- **时间**：每月最后一个周末，60分钟
- **参与者**：核心成员 + 医学专家（可选）
- **内容**：
  1. 月度目标达成情况
  2. 经验教训总结
  3. 下月计划与调整
- **产出**：月度报告

### 临时会议

#### 触发条件
- 重大技术决策需要讨论
- 阻塞性问题需要快速解决
- 重要功能需求评审

#### 会议规范
- **提前24小时**通知，附带会议目标与准备材料
- **控制时长**：30分钟内，最多60分钟
- **明确产出**：决策结果、行动计划、责任人
- **会后归档**：24小时内更新飞书文档

### 会议替代方案（推荐）

#### 异步决策流程
1. 发起人在飞书创建决策文档
2. 描述问题背景、可选方案、推荐方案
3. @相关成员评论反馈（48小时内）
4. 达成共识后标记决策结果
5. 无共识则发起短会（15分钟）讨论

## 四、任务管理机制

### 飞书多维表格 - 任务看板

#### 字段设置
| 字段 | 说明 | 示例 |
|------|------|------|
| 任务名称 | 简洁描述 | 完成知识库Embedding优化 |
| 负责人 | 单一责任人 | @张三 |
| 协作人 | 需要配合的人 | @李四 |
| 状态 | 当前状态 | 待开始/进行中/待审核/已完成 |
| 优先级 | P0/P1/P2/P3 | P0-本周必须完成 |
| 截止日期 | 明确deadline | 2025-12-15 |
| 关联文档 | 飞书文档链接 | [技术方案] |
| 备注 | 补充说明 | 依赖XX任务完成 |

#### 任务状态流转
```
待开始 → 进行中 → 待审核 → 已完成
                ↓
              阻塞中（标注阻塞原因）
```

#### 任务更新频率
- **负责人**：每周至少更新一次状态
- **项目发起人**：每周审查一次看板
- **更新方式**：直接在表格修改，无需单独汇报

## 五、异步协作最佳实践

### 1. 提问的艺术

❌ **低效提问**：
> "在吗？"  
> "RAG怎么搞？"  
> "有个问题想问一下"

✅ **高效提问**：
> "【技术问题】FastGPT的知识库Embedding选择  
> **背景**：正在处理医学术语的向量化  
> **问题**：text-embedding-ada-002 vs bge-large-zh，哪个更适合中文医学文本？  
> **已尝试**：查阅了文档，倾向bge-large-zh  
> **需要**：@RAG工程师 确认方案，或推荐其他选项  
> **时效**：本周五前需要确定，以便推进知识库构建"

### 2. 进度汇报模板

**每周异步汇报**（周日晚发飞书文档）：
```
【本周完成】
- ✅ 完成了XX功能开发
- ✅ 整理了XX份医学文献

【下周计划】
- 🎯 完成XX模块测试
- 🎯 启动XX功能开发

【需要协助】
- 🆘 XX问题需要@医学专家确认
- 🆘 XX技术点需要@RAG工程师指导

【风险提示】
- ⚠️ XX任务可能延期1周（原因：...）
```

### 3. 文档编写规范

#### 标题结构
- 使用Markdown格式
- 清晰的层级结构（H1/H2/H3）
- 关键信息加粗或高亮

#### 必备要素
- **目标/背景**：为什么要做这件事
- **方案/内容**：具体怎么做
- **结果/结论**：达成了什么
- **下一步**：后续行动计划

#### 协作标注
- 使用 `@成员名` 请求反馈
- 使用高亮标注待确认内容
- 使用评论功能讨论细节

  - 技术问题响应（工作日24小时内）
  - 代码审查（PR提交后48小时内）

## 七、应急响应机制

### 紧急事项定义
- **P0紧急**：系统崩溃、数据丢失、严重医学错误
- **P1重要**：功能故障影响测试、上线阻塞问题
- **P2一般**：体验问题、优化建议

### 响应流程

#### P0紧急事项
1. 微信群 `【紧急】` 标题 + @项目发起人 + @相关技术负责人
2. 同时创建GitHub Issue标记 `urgent`
3. 响应时间：2小时内（无论工作日/周末）
4. 必要时拉临时会议快速解决

#### P1重要事项
1. GitHub Issue 或飞书文档描述
2. @相关负责人
3. 响应时间：工作日12小时内，周末24小时内

#### P2一般事项
1. 正常流程提交Issue或文档
2. 按常规响应时效处理

#### 每月（异步 + 可选同步）

## 九、新成员融入机制

### 入职第一周
1. **欢迎仪式**：微信群欢迎 + 自我介绍
2. **文档阅读**：项目README、团队架构、本沟通指南
3. **权限开通**：飞书、GitHub、Notion等工具
4. **破冰任务**：一个小任务（1-2小时），熟悉流程

### Buddy制度
- 为新成员指定一位Buddy（经验丰富的成员）
- Buddy负责：
  - 回答新成员问题
  - 引导熟悉工具和流程
  - 第一个月每周至少一次沟通（可异步）

### 新成员提问优先级
1. 先查阅文档（飞书知识库）
2. 使用AI助手获得初步答案
3. 询问Buddy
4. 在微信群/GitHub提问

## 十一、文化与氛围

### 我们鼓励
- ✅ 主动分享学到的知识和经验
- ✅ 提出建设性意见和优化建议
- ✅ 承认不懂并寻求帮助
- ✅ 实验新方法并分享结果

### 我们避免
- ❌ 频繁打扰他人
- ❌ 在私聊中做重要决策（应公开讨论）
- ❌ 批评他人的贡献方式

2. 无法解决时，寻求项目发起人协调
3. 以项目目标为导向，不纠结个人得失
4. 记住：我们都是志愿者，相互尊重最重要

## 总结：沟通三原则

### 1️⃣ 少而精
- 减少沟通频次，提高沟通质量
- 能异步就不同步，能文档就不会议

### 2️⃣ 异步优先
- 尊重每个人的时间和节奏
- 给予充分的思考和响应时间

### 3️⃣ 结果导向
- 每次沟通有明确目标和产出
- 聚焦可交付成果，不纠结过程

---

**记住：我们的沟通目标是让项目高效推进，而不是让大家感到被打扰和疲惫。**

**让我们一起创造一个高效、友好、专业的协作环境！** 🚀
